# AI Image — один плагін Photoshop замість двох

Замінює `NanoBananaPluginPS` і `GPT-imagePluginPS`. Один сценарій:
**прямокутне виділення → промпт → провайдер/модель/якість → Smart Object точно на місці.**
Працює в RGB і CMYK, 8/16/32 біт.

## Встановлення

```bash
cp -R ~/ai-image-ps "/Applications/Adobe Photoshop 2026/Plug-ins/AiImagePS"
```

Потім перезапустити Photoshop. Панель: **Plugins → AI Image**.

Розробляти краще тут (`~/ai-image-ps`), а в `Plug-ins` копіювати — у старих плагінах
всередині `Plug-ins` лежали повні git-репозиторії з демо-гіфками (77 МБ `.git` + 22 МБ
`doc-assets` при 250 КБ коду), а Photoshop сканує цю папку при кожному старті.

Оновлення після правок:

```bash
rsync -a --delete --exclude '.git' --exclude 'node_modules' ~/ai-image-ps/ "/Applications/Adobe Photoshop 2026/Plug-ins/AiImagePS/"
```

**Ключі API доведеться ввести заново** — `secureStorage` в UXP ізольований per plugin id,
тому ключі зі старих плагінів сюди не переїдуть. Потрібні два: OpenAI і Google (кожен
запитується при виборі відповідного провайдера).

## Перед першим використанням: перевірити передумови

Три речі неможливо підтвердити документацією — Adobe не документує batchPlay-ID узагалі.
Скрипт їх міряє в живому Photoshop:

**File → Scripts → Browse… → `verify-assumptions.psjs`**

Створює власні тестові документи, міряє, закриває їх без збереження. Документи користувача
не чіпає. Звіт — на Робочому столі і в консолі.

Що саме перевіряється:

| # | Питання | Чому важливо |
|---|---|---|
| 1 | Координатна система `smartObjectMore.transform` | основний канал вимірювання в `place.js` |
| 2 | `transform rectangle→quadrilateral` як масиви | несуча ідея: абсолютна рамка замість відсотків |
| 3 | Що робить `placedLayerResetTransforms` | страховка від PPI-масштабування |
| 4 | `resizePastePlace` через `generalPreferences` | гасить fit-to-canvas |
| 5 | **Чи `place` конвертує CMYK/16-біт документ** | **несуча передумова всієї архітектури** |
| 6 | Чи `pHYs` усуває PPI-масштабування | `setPngResolution` у `png.js` |
| 7 | `componentSize:8` з 16-бітного документа | чи потрібен шлях через дублікат |
| 8 | `getPixels` у CMYK — вимкнено, бо валить Photoshop | обґрунтування шляху через дублікат |

Якщо тест 5 покаже «КОНВЕРТУВАВ» — архітектуру вставки треба міняти, скажіть мені.
Тести 1-4 можуть показати «НЕ ТАК» — `place.js` це переживає (є резервний канал і гейт
правдоподібності), але точність тоді не гарантована, і код треба підправити під фактичну
поведінку.

## Головна метрика точності

Після кожної вставки в консолі:

```
[main] вставка 1/1: residual {"dx":0,"dy":0,"dw":0,"dh":0}
```

`residual` — розбіжність між тим, куди мав стати Smart Object, і куди він став насправді.
**Мусить бути нулем.** Якщо ні — це те саме «вставка не завжди точна», і числа скажуть, де саме.

Перевірочна матриця: 3 документи (RGB 8 біт 2000×1500 300 ppi; CMYK 16 біт; RGB 16 біт
800×600 72 ppi — канва менша за 1024, щоб зловити fit-to-canvas) × 3 виділення
(200×200 парне, 201×201 **непарне** — саме на ньому старий код давав +1 px,
і 1000×600 при непропорційній відповіді).

У CMYK-документі в палітрі History **не має з'явитися жодного «Convert Mode»**,
а `mode` і `bitsPerChannel` мусять лишитися незмінними.

## Архітектура

```
main.js       406  єдиний потік: гейт → capture → provider → place. Нічого більше.
place.js      298  вставка: pHYs → placeEvent → вимір → абсолютна рамка → доводка
capture.js    189  захоплення: RGB/Gray/Lab напряму, решта через ДУБЛІКАТ документа
geometry.js   206  уся арифметика; чистий модуль, тестується в node
png.js        300  PNG + справжній deflate (маска 1024² = 15 КБ замість 4 МБ)
providers/
  index.js     28  реєстр
  http.js     157  fetch зі скасуванням, ретрай 429 з Retry-After
  openai.js   164  gpt-image-2 (довільний розмір) + gpt-image-1/1.5/mini
  google.js   199  gemini-*-image, imageConfig із graceful degradation
auth.js       130  ключі, по одному на провайдера
presets.js     86  пресети промпту (без змін)
history.js     71  історія (без змін)
```

Додати третього провайдера = один файл у `providers/` + один рядок у `index.js`.
`main.js` про провайдерів не знає нічого — саме через це двом окремим плагінам більше
немає причини існувати.

### Чому так, а не як раніше

Стара архітектура **передбачала** геометрію: рахувала позицію наперед у JS із ланцюга
незалежно округлених величин, а тоді віддавала результат двом API, які половину переданого
молча відкидають (`putPixels` читає з `targetBounds` лише `left`/`top` — «Dimension keys
width and height are not used»). Зворотного зв'язку не було ніде.

Нова **міряє**: кладе, читає фактичну рамку через `smartObjectMore.transform`, виставляє
абсолютні цілі координати чотирьох кутів, перечитує, доводить цілим пікселем. Кожен виклик
перезаписує геометрію, а не додає до неї відсоток — тому накопичення похибки неможливе.

І друге: `putPixels` фізично не приймає CMYK (`createImageDataFromBuffer.colorSpace`
документує лише RGB/Grayscale/Lab), тому старий код конвертував **увесь документ**
CMYK→RGB→CMYK — необоротно, бо відкат історії зняв би й саму вставку. `placeEvent` з файлу
imaging API не торкається взагалі.

## Що зникло проти старих плагінів

Вкладки Grid і Chat (711 рядків `chat.js`), Refine-prompt, Whole-Image/Gen-Fill, Upscale
(був повним no-op через `CONTEXT_PAD=0`), Reference images (захоплювались, але в `options`
не потрапляли — мертвий тракт), `saveDebugBlob` (намив 2.97 ГБ у 484 файлах),
`encodeAs8BitJpeg` (16→8 через `>>8` при діапазоні `[0..32768]` → вдвічі темніше),
мертві моделі (весь Imagen — вимкнений 2026-08-17, `gemini-1.5-*`, `gemini-2.0-flash-exp`),
`generateImageWithContext` із `/v1/responses` (імпортувався, не викликався ніде).

~2250 рядків геть. Було 5289 у двох плагінах, стало 2520 в одному — і при цьому додано
двох провайдерів в одному UI, коректну геометрію й безпечний CMYK.


Лишаються на місці й працюють. Обидва репозиторії чисті, тому відкат будь-коли:

```bash

```
